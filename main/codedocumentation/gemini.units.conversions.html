gemini.units.conversions

Unit conversions at package and correlation boundaries; historical factors retained.

The *_to_* functions convert at correlation boundaries that use US or laboratory units. _UNITS is the single table of public data units: every unit maps to its SI unit, a scale and an offset, si = value * scale + offset. Unit, the enum of the units, is generated from it, and to_si, convert, value_in_si, si_unit, names, fits and the unit sets of Profile and Stream all read it. define_quantity records the SI unit of each named quantity (the types package calls it once per quantity), so names(quantity) and fits(unit, quantity) need no upward import.

Each conversion factor is declared once, as a named module constant below, and both the table and the converters read that constant.

Validity: every converter is valid for any finite number; the argument is returned scaled (and offset for temperatures), with no range check. Source: NIST Special Publication 811 (2008) for the exact definitions (bar, inch, foot, psi, hour, degree Celsius). Where a value is a retained number of the original GEMINI (the millidarcy, barrel per day, foot of head, brake horsepower, lbm/ft3 and psi factors), that historical factor is kept bit for bit, whatever its digits.

The converters are not decorated with @ops.physics: they sit on the hot path of every binding and plain operators work on every backend, so the registry wrapper would only add cost.
