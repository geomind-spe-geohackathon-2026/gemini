gemini.compiler.ir

The intermediate form: a computation graph of nodes, its loop bodies and its inputs and outputs.

A Graph is what the tracer records for one module call: ordered Node objects (a graph input, or one op applied to earlier nodes) with named inputs by role, named outputs and checks. The kinds of node are the op kinds of gemini.ops.registry, the loop nodes fixed_point (a Body run until every row settles) with its carry and loop_output nodes, and the node scan (a Body run once per row with the states carried from row to row) with its scan_output nodes.

The body of a loop: the nodes of one pass around it, run by a fixed_point node.

A plant that closes a loop records one pass around it as a body, in the same graph: carry nodes stand for the fields of the tear streams, the nodes of the pass follow (they refer freely to the nodes of the outer graph), and one fixed_point node, whose operands are the first guess of every carry and the temperature limits, runs the body on the interpreter until every row has settled. Its outputs are loop_output nodes: the converged value of each carry and active, the rows that did not converge. The nodes of a body belong to it (Node.body) and the outer passes skip them; so does common-subexpression elimination, which merges only inside one body.

watch are the nodes of every outlet of every step of the pass and the values that physics requires (ops.require), unframed the checks of the pass that no physics function owns: a row that gets an error into either stops iterating, as a row does that fails a pass alone. The checks of a body never reach an output of the graph.
