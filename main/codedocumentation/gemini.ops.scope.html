gemini.ops.scope

The eager physics scope: @ops.physics and the scope a module call enters.

A direct call of a module or a physics function is eager: the same forward and the same ops as the graph, evaluated on the Python backend. One mechanism makes plain operators safe there:

  • Entering the outermost scope enters np.errstate(all="ignore") and gives a function called on plain Python numbers its arguments as NumPy scalars: an exact float as np.float64, an exact int as np.int64, which prints, indexes and loops as an int (bool, None, strings, arrays and traced values pass through). They have the arithmetic of Python numbers but / by zero, an invalid ** and an overflow give inf or nan silently, like the NumPy and graph backends. Arrays or traced values among the arguments leave the scope unwrapped (an np.float64 scalar would promote a float32 array), and so does a module whose Module._scalar_mode is PLAIN (the ESP under float32 precision, the one quirk).

  • Nested scopes only wrap the exact numbers among their own arguments (a literal 0.0) and catch a failing check; the cost is a ContextVar read and a scan of the arguments.

  • Leaving the outermost scope returns plain Python scalars on every backend: float for np.float64, bool for np.bool_, recursively through tuples, lists, dicts and frozen dataclasses, and raises the error of a Failed found anywhere in the result.

  • A failing check (ops.check on concrete scalars) raises a marked error; physics returns Failed(error) for it at each function boundary (see gemini.ops.failed). Outside any scope the caller sees the real error. A failing check on an eager array raises at once, for its first failing row, and is never turned into a Failed; the eager executor asks for gemini.ops.failedrows.marking instead, and then the failing rows of a physics function travel with its results as FailedRows, the array counterpart of Failed.

  • In a trace (tracing(graph)) a physics function keeps the checks recorded directly in it and guards every traced value it returns with them, so the graph attaches an error to the results of the function exactly as the eager Failed does. A check recorded outside any physics function is certain: it guards every graph output, as it raises at once when eager.

  • A result used for its validity only is passed to require, or its error is dropped.

Do not put repr of a physical value in a message (np.float64(1.0)), and note that round(np.float64, n) is NumPy’s rounding: use ops.round.
