gemini.compiler.passes.cse

Common-subexpression elimination: merge nodes with the same op, operands and attributes.

eliminate_common_subexpressions(graph) rewrites the graph in place in one forward sweep over the nodes in creation order. A node is a twin of an earlier node when its op, its operands (after the operands themselves were merged), its literals and its attributes are identical. Operand identity is a node by the merged node and a literal by type and exact value: 1, 1.0 and True differ, 0.0 and -0.0 differ, NaN equals itself. Graph inputs and ops of the reduction, interp, solver and scan kinds are never merged.

Errors. A node carries the error codes of its operands and of its guards, and where keeps only the codes of its selected branch. Merging twins gives the survivor the union of their guards, which can only add an error to the consumers of one twin. That is harmless when the added error already reaches a graph output on every row where it fires, because the error that is raised is the lowest code over all outputs; it is wrong when the twin sat in one where branch and the error belonged to the other. A node is therefore certain when it reaches a graph output through operands that are not a where branch. Two twins merge only when each of them is certain or has no guards. A node whose guards stay below a where branch merges with nothing, so no error moves onto a branch it did not belong to.

Checks merge like any other node: same condition, error class, message and message values. The merged check keeps the lowest code, codes are renumbered in creation order, and the traced message values of every check and the proxies of Graph.result follow the merged nodes. The pass costs one dictionary lookup per node.

Functions
