gemini.modules.module

Equipment modules: declarations and children registered in __init__, called with inlets.

A module registers what __init__ assigns: Parameter, Port (its inlets and outlets, by direction), Control, Boundary, State and Output declarations go to ordered registries and Module values become children with dotted paths. A module is written as two pure methods: forward(self, inputs, inlets, state) -> (outputs, outlets) and, if it has states, update(self, inputs, inlets, outlets, state, dt) -> state. They write nothing to self, which holds the parameters only. Calling a module validates the inlets, resolves the controls and boundaries into inputs, runs the forward pre-hooks, forward, the check of the returned keys and the forward hooks, then returns a ModuleResult.

The values of one call live in a CallRecord (gemini.modules.callrecord), the only per-call state. The parts of a module that are separate jobs are in their own files: the arguments of a call (callargs), the state tree and the step (states), the display (display), the path of a class (classpath).
